# SABATHIA — Decision Engine v1.0

> Your time, intelligently organized.

플래너의 일정을 읽고, 해야 할 일과 남은 시간의 관계를 계산해, **지금 가장 중요한 행동**을 보여주는 개인 의사결정 PWA.

- **규칙 기반 판단** — 일정·우선순위 판단에 AI 호출 없음
- **기존 플래너 = 데이터 원본** — 시간 블록 길이를 예상 소요 시간으로 읽음
- **스마트폰 우선**, iPad 가로/데스크톱에서는 창형(OS 스타일) 배치
- **오프라인 동작**, 데이터는 기기 브라우저(localStorage)에만 저장

## 실행

빌드 과정이 없습니다. 정적 서버로 열면 됩니다.

```bash
npm start            # python3 -m http.server 8080 → http://localhost:8080
```

```bash
npm test             # 판단 엔진 테스트 (Node 20+)
```

개발·검증용으로 `?now=2026-11-18T21:00` 을 붙이면 현재 시각을 고정할 수 있습니다.

## 사용 흐름

1. **일정** 탭: 요일별 기상·취침, 학교·학원·이동·식사 같은 고정 일정 입력 (한 번만)
2. **플래너** 탭: 평소처럼 시간 블록 작성, 또는 기존 플래너 텍스트를 그대로 붙여넣기
   ```
   11/18 (수)
   19:00-21:00 수학 숙제
   21:00-22:00 국어 숙제 마감 11/20
   [x] 22:00-22:30 영어 단어
   수학 오답 정리 40분
   ```
3. 끝나면 **완료 표시만**. 예상보다 크게 늦어질 때만 "남은 시간" 수정
4. **홈**이 상황에 따라 메인 카드를 자동으로 바꿔 보여줌

## 구조

```

  time.js            시간 유틸

  capacity.js        요일별 기상·취침 + 고정 일정 → 자유 시간 창 (수면 제외)
  simulate.js        다일 일정 시뮬레이터 (마감 보호 EDF 검사 포함)
```

## 판단 엔진 동작

1. **가용 시간**: 오늘부터 최소 7일(마감·시험이 멀면 최대 28일)의 자유 시간 창을 만든다. 취침~기상, 고정 일정은 절대 쓰지 않는다.
2. **작업 → 배치 단위**: 남은 시간 × 과목별 오차(낙관/예상/비관 3개 시나리오). 마감(hard)과 계획한 날(soft)을 구분.
3. **배치 순서**: 유효 기한 → 우선 등급 → 사용자가 계획한 시작 시각 → 과목 순위.
   - 우선 등급: 수행평가 > 숙제 > 기타 > 복습 > 프로젝트 (시험 집중 모드에서 시험 과목 복습·시험 공부 상승, 시험 직전엔 숙제보다 위)
   - **마감 보호**: 다음 작업을 고를 때마다 "이걸 먼저 하면 마감 작업이 늦어지는가?"를 비관 시나리오로 검사
4. **기준 계획 vs 지연 계획**: 지금 시작 vs N분(기본 30) 후 시작을 비교해 마감 부족·복습 손실·다음 날로 밀리는 작업을 계산.
5. **메인 카드** (우선순위 순): 휴식 → 마감 위험 → 지금 시작(지연 손실) → 빠듯함 주의 → 시험 집중 → 장기 프로젝트 → 다음 작업 → 오늘 끝.

### 손실 알림 원칙

- 숙제가 다음 날로 밀려도 **마감이 안전하면 경고하지 않음** (정보로만 표시)
- 경고는 마감 부족이나 복습 손실이 기준(기본 15분) 이상일 때만
- 숫자는 범위로: `약 20~40분`, 비관 시나리오에서만 생기면 `최대 약 30분`

### 남은 시간 수정 — 일정 비용 vs 학습 가치

수정 사유(문제 난이도 / 개념 다시 확인 / 생각보다 빠름)를 함께 기록합니다. 늘어난 분은 **일정 비용**으로 이후 일정에 반영하되, "개념 다시 확인"은 **학습**으로 따로 기록해 낭비로 취급하지 않습니다. 이 기록은 설정의 과목별 오차 범위 옆에 누적되어, 이후 임시값을 보정하는 근거가 됩니다.

## Sabathia WS — 새 판단 엔진 (`ws/`)

`design/ws-draft/`의 초안 화면(NOW · TODAY · DEADLINES · PLANNER 창)을 그대로 쓰고, 그 화면의 숫자와 경고를 모두 새 판단 엔진이 계산합니다. 초안에 직접 적혀 있던 "약 1시간 부족" 같은 문구는 더 이상 없습니다.

- 열기: `npm start` → `http://localhost:8080/ws/` (배포 후 `/ws/`)
- `?now=2026-11-18T18:58` 시각 고정 · `?reset` 샘플 다시 불러오기
- 데이터는 이 기기 브라우저(localStorage `sabathia.ws.v1`)에만 저장
- 실제 데이터: 위쪽 '샘플 데이터' 버튼 → Sabathia 주소(기본 `sabathia.oasilsu0829.workers.dev`)·토큰(설정했을 때만)·15577 온라인 저장 ID. 일정은 `/api/events`, 블록은 Firestore `planners/{ID}`에서 읽기만 한다(`ws/live.js`). 연결 정보는 이 기기 `sabathia.ws.src`에만, 저장소에는 개인 데이터를 넣지 않는다. 열 때·5분마다·화면으로 돌아올 때 다시 읽고, 숙제 진행(타이머로 센 분량)은 큰 쪽을 남긴다
- 첫 화면: 창 네 개는 닫혀 있고 '지금 할 일'만 크게. 코로나 일정 시계는 첫 화면에서 뺐고 `ws/corona.html`에서 따로 볼 수 있음
- 배경: Unsplash 사진 한 장(`ws/bg.webp`, Photo by ran liwen on Unsplash). 주소 끝 `#city`면 같은 도시를 2시간마다 찍은 사진 12장(`ws/city.js`), `#city=14`로 시각 미리보기

### 판단 순서 (`ws/engine/judge.js`)

1. **남은 시간 = 남은 분량 × 페이스**, 낙관/예상/비관 3개 시나리오. 근거 순서: 직접 푼 기록(타이머 + "1문제 완료") → 적어 둔 1문제당 시간 → 같은 학원·같은 단위의 기록 → 플래너 블록 시간 → 없으면 추측하지 않음("진행 후 추정")
2. **플래너 배정**: 블록 시간을 블록 안 숙제에 마감이 빠른 순서로 필요한 만큼 나눠 줌. 못 들어간 숙제는 "일부 안 들어감"
3. **마감 검사**: 계획에 못 들어간 나머지를 *아무 블록도 없는 빈 시간*에 마감 순(EDF)으로 넣어 봄. 수면·학교·학원·식사 시간은 쓰지 않음
   - 예상 시나리오에서도 마감 전에 못 끝냄 → **마감 전 끝내기 어려움** (빨강)
   - 비관 시나리오에서만 못 끝냄 → **빠듯할 수 있음**
   - 끝낼 수는 있지만 계획이 15분 이상 모자람 → **계획 더 필요** (경고 아님)
4. **오늘 꼭 필요**: 나머지를 마감 직전부터 거꾸로 채워도 오늘에 걸리는 분량 → TODAY의 "계획 밖 필요"
5. **NOW 판단**: 지금 블록이면 먼저 할 숙제와 배정 시간, 블록 사이 빈 시간이면 넣을 숙제, 학원 중이면 다음 블록, 취침 후면 휴식. 30분 미루면 마감이 깨질 때만 "지금 시작" 경고

테스트: `tests/ws-judge.test.js`
